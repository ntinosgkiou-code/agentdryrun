# Changelog

## 0.8.0 (2026-10-26)  Rules that fit you, and a live hook (experimental)
- **`scan --write-rules FILE`**: writes a copy of the starter pack in which the kinds of action that do not appear in your history get a first deny rule ("locked"), and the kinds you use keep the starter rules. Needs 200 judged actions, otherwise it locks nothing and says so. Verified on a real 90-day history (7 kinds locked, 6 kept; the same verdicts as the pack on that history, as it must be).
- **`python -m agentdryrun hook`** (experimental): the same rules applied live as a Claude Code PreToolUse hook. Refused: `deny`; needs approval: `ask`; would pass: no output, so the normal permission flow decides (it never answers `allow`). `--mode observe --log FILE` judges and logs without blocking. `--print-settings` prints the settings.json block (exec form, ASCII-safe, so it works the same on Windows, macOS and Linux). Protocol read from the hooks documentation and tested with simulated calls; **not run inside a live Claude Code session**.
- Packaging: SPDX license expression, project URLs, the rules pack declared as a package; the wheel and sdist pass `twine check` and a clean-venv install runs `scan`. `.github/workflows/publish.yml` publishes to PyPI on a release via trusted publishing (needs a one-time pending publisher on pypi.org, so the package is **not yet on PyPI**).
- New page: [What did your coding agent do last month?](docs/blog/what-did-your-coding-agent-do.html).
- A test of the hook caught a real bug: printing JSON with non-ASCII characters through a Windows console code page produced text a JSON parser would reject (and a hook answer that cannot be parsed fails open). Output is now ASCII-escaped.
- 142 tests.

## 0.7.1 (2026-10-25)  Install it from inside Claude Code
- **Claude Code plugin.** The repository is now also a plugin marketplace (`.claude-plugin/marketplace.json`) with one plugin (`agentdryrun`) and one skill, `/agentdryrun:scan`: `claude plugin marketplace add ntinosgkiou-code/agentdryrun`, then `claude plugin install agentdryrun@agentdryrun`. Checked with `claude plugin validate --strict` and by installing it into a throwaway Claude Code config from a local copy; the scan command it runs was run from the installed copy. **Not checked:** running the skill inside a live Claude Code session (the headless run in this environment could not authenticate), installing from the GitHub address before it was published, Windows PowerShell form of the command, and the plugin on claude.ai or Cowork (it needs a local Python).
- `tests/test_packaging.py` keeps the version in `pyproject.toml`, `package.json`, `plugin.json` and `CITATION.cff` equal and pins the skill's safety properties.
- 119 tests.

## 0.7.0 (2026-10-25)  `scan`: a dry run on your own coding agent's history
- **`python -m agentdryrun scan`** reads the Claude Code transcripts on your machine (`~/.claude/projects`), names what the agent attempted (recursive deletes by how far from the project they reach, force pushes, `curl | sh`, secret files read, uploads, destructive database and cloud commands, writes to agent settings, CI files and shell startup files, MCP tools that look like they change things), judges every action against a starter rules pack as a dry run, and writes one HTML report card: what would pass, what would need approval, what would be refused, where the tool output piled up and which calls failed repeatedly. Read-only; nothing is sent anywhere. A scan of 30 days over 438 MB of transcripts takes about 3 seconds.
- Rules pack `agentdryrun/packs/coding-agent.json` (21 tools, validated by `rules check`); `--rules` takes your own. `--no-previews` leaves command text out of the report; commands shown are cut to 140 characters and keys, tokens and passwords are hidden on a best-effort basis. `--events-out` writes the derived events so `shadow` can run them against other rules; `--max-refused` / `--max-pending` exit with code 4 for CI.
- Shell parsing that avoids the obvious false alarms (found by running it on a real 90-day history, not only on invented commands): here-document bodies and quoted text are not commands, `cd` and `NAME=value` earlier in the same command move where `rm -rf` points, `curl ... | python -c` only reads the download, `find . -name '*.pyc' -delete` is not "delete the project".
- New sample: `examples/claude-code-sample/` (48 invented tool calls, generated by `tools/make_claude_sample.py`), a sample report card at `docs/agent-report-card.html`, a terminal recording (`docs/assets/scan.gif`).
- README and landing page now lead with `scan`; the rest (recorder, MCP proxy, Langfuse/LangSmith/OpenTelemetry readers, verifier, witness) is unchanged.
- **Not covered:** Codex, Cursor and other agents; the transcript format is not a documented interface and was read as it looked on 2026-10-25. Pattern matching misses scripts and run-time paths.
- 114 tests.

## 0.6.0 (2026-10-25)  Fewer steps to the first report
- **`mcp-record`**: a stdio proxy that starts any MCP server, forwards every message unchanged in both directions and copies each `tools/call` request into an events file before the server sees it. No change to the agent or the server. Tested byte for byte against a fake server, and between the official MCP Python SDK client and a server written with it (SDK 1.30 and 2.3, Linux and Windows CI: `mcp-compat.yml`). **Not tested** against desktop clients (Claude Desktop, Cursor, VS Code) or non-Python servers; stdio only.
- **`suggest-rules`**: drafts a first rules file from the events: tools whose names look read-only need no approval, everything else (and anything unrecognised) needs one approval. Never writes limits, refusals or escalations; prints the numeric fields it saw instead. Output passes `rules check` and is marked `REVIEW ME`.
- **JavaScript/TypeScript recorder** (`js/`, `package.json`): the same `Recorder` for Node 18+, zero dependencies, same events file. Install from GitHub; not published on npm.
- Fixed while testing against the official SDK: the proxy crashed ("Fatal Python error") when the server exited while the client still held stdin open. It now flushes and exits with the server's exit code. A test pins it.
- GitHub Action example pinned to `v0.6.0`.
- 92 tests (plus 7 in Node, 1 integration check run in CI).

## 0.5.0 (2026-10-25)  New name: agentdryrun
- **Renamed from OmniOS to agentdryrun.** OmniOS is the name of an unrelated, actively released operating system (omnios.org), which made the project impossible to find and risked confusion. Python package, commands (`python -m agentdryrun`, `agentdryrun-verify`), repository (`ntinosgkiou-code/agentdryrun`; the old URL redirects), docs and tests all use the new name. The old repository URL keeps working through GitHub's redirect.
- **Kept on purpose:** the evidence-bundle format identifier `omnios-evidence-bundle` and the `omnios/<tenant>` origin prefix inside the signed examples. They name a format, not the project, and changing them would invalidate existing bundles.
- README leads with the problem and a one-line analogy (a dry run for AI agents, like `terraform plan`), badges for Python, dependencies and licence; "independent witness" is now "witness service" everywhere (independence depends on who runs it).
- Regenerated the demo recording, the report screenshot and the social preview image.
- **GitHub Action** (`action.yml`): runs the dry run in CI and fails the build (exit code 4) when more actions would be refused, need approval or use a tool no rule covers than you accept; writes a job summary table and uploads the HTML report. New flags on `shadow`: `--max-refused`, `--max-pending`, `--max-unmapped`, `--summary-md`. Self-tested in this repository's CI on Linux and Windows, including the failing case.
- 74 tests.

## 0.4.0 (2026-10-24)  Record your own agent
- `omnios.record.Recorder`: two lines (`@rec.tool("name")`) write an agent's tool calls to a local events file before each call runs. Sync and async, threads, `rec.wrap` for code you cannot edit. Keeps only short scalar parameters and, with `rules=`, only the fields the rules look at. Never breaks the agent (one warning if the file cannot be written). Records the attempt only.
- `examples/agent_demo.py` + `examples/rules-front-office.json`: a toy front-office assistant (50 invented calls: book, cancel, invoice, refund, message, win-back) and the rules for it; tests pin the verdicts (37 pass, 11 need approval, 2 refused) and check that names and message bodies never reach the file.
- `pyproject.toml`: `pip install git+https://github.com/ntinosgkiou-code/omnios` gives the `omnios` and `omnios-verify` commands and the `Recorder` import (checked in a clean virtual environment). Optional extra `[witness]`.
- `shadow` no longer prints the "no --permissions" note when the rules name no permission.
- 68 tests.

## 0.3.0 (2026-10-24)  Verifier hardening
Found by attacking our own verifier (`tests/test_adversarial.py`, 19 cases; an earlier exploratory run of 76 hostile bundles).
- **Fixed: silent omission.** A bundle with records removed and its unsigned `scope` label changed verified with no warning. `verify.py` now warns `INCOMPLETE` whenever the bundle holds fewer records than the signed checkpoint covers, and `--require-all` makes it a failure.
- **Fixed: crashes.** 24 of 76 hostile bundles (missing or damaged files, wrong JSON types, deep nesting) ended in a Python traceback and exit 1. They now end in a clean FAILED or unreadable result (exit 2 or 3). Never `VERIFIED`, before or after.
- **Fixed: unbounded read.** A 327 KB zip inflating to 300 MB was read whole (~600 MB of memory). Members above `--max-bytes` (default 256 MiB) are refused before reading; duplicate zip entry names and more than 64 entries are refused.
- Stricter `records.jsonl`: each record once, ascending, with correctly typed fields (repeating or swapping lines used to pass harmlessly; it now fails).
- `--log-key` and `--witness` keys are validated (32-byte base64) with a clear message.
- Docs: README no longer says the verifier checks that records were "not removed" without qualification; three rules for whoever receives a bundle; removed two references to files that exist only in the private repository.
- Importers: field names checked against the OpenTelemetry, Langfuse and LangChain primary sources; Langfuse `fields=core,basic,io` caveat documented.
- 58 tests.
