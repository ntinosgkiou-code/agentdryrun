agentdryrun

What did your coding agent actually do last month?

Anthropic reports that users accept 93% of Claude Code's manual permission prompts. One command reads the session history Claude Code already keeps on your machine and shows what your rules would have stopped: recursive deletes, force pushes to main, curl | sh, secret files read, files sent to other hosts, destructive database and cloud commands. Think terraform plan, but for what your agent did. Read-only, local, zero dependencies, nothing is sent anywhere.

Try it on your own history

git clone https://github.com/ntinosgkiou-code/agentdryrun && cd agentdryrun && python -m agentdryrun scan

Python 3.9 or newer. Nothing to install. Reads ~/.claude/projects (last 30 days) and writes agent-report-card.html. Use --no-previews before you share the page. Claude Code only, for now. Or inside Claude Code: claude plugin marketplace add ntinosgkiou-code/agentdryrun, then claude plugin install agentdryrun@agentdryrun and /agentdryrun:scan.

Under the scan: a dry-run engine for any agent

1. RecordTwo lines around your agent's tool functions (Python or JavaScript) write every call to a local file, before it runs. It never breaks your agent. Or put mcp-record in front of any MCP server and change nothing else.
@rec.tool("refunds.issue")
def issue_refund(customer, amount_eur): ...
2. Dry runA rules file says what may pass, what needs approval, what is refused. The report shows what would have happened, and which tools no rule covers. suggest-rules drafts the first rules file for you. Runs in CI as a GitHub Action.
3. ProveA one-file verifier checks an evidence bundle offline: records unedited, signed by the key you pinned, rules followed, and it tells you when records are missing.

In CI

- uses: ntinosgkiou-code/agentdryrun@v0.7.1
  with:
    rules: rules.json
    events: tests/agent-events.jsonl
    max-refused: 0
    max-unmapped: 0

Fails the build when your agent would do more than you accept. Reads Langfuse, LangSmith and OpenTelemetry exports too.

What it is not

A prototype with no external security review. It does not certify anything, does not make you compliant with any regulation, and does not stop prompt injection. The recorder logs attempts, not outcomes or approvals. The example data is invented. Read the known limits.

Help wanted

The most useful thing you can do: try it on a real export and tell us if it fails, or try to break the verifier. Open issues include good first issues.

Apache-2.0. Built in public: the build log records what worked and what was wrong.
